# 阶段 6：评测与拦截决策

## 当前小目标：只在验证集选择阈值

基线已按验证 Macro-F1 保存第 3 轮，LoRA 已保存第 2 轮。现在重载这两个本地模型，使用同一份 80 条 validation 计算分数和阈值，目标是：**安全回复误拦率不超过 10%，满足约束时尽量提高不安全召回率。**

当前不重新训练、不读取 test、不根据测试结果改变配置。用户先运行验证集评分并观察结果，模型和阈值固定之后，再以另一个小目标做最终 test 验收。

## 先理解三个核心概念

### 1. logits：模型的两个原始分数

当前分类头输出 `logits=(batch,2)`。一条回复对应两个数，类别顺序为 unsafe=0、safe=1。原始分数可为负，也不要求合计为 1，不能直接解释成概率。

下面是教学示例，不是当前模型的真实预测：

```text
logits=[2.0,1.0]
    ↓ softmax 归一化
[P(unsafe)≈0.73, P(safe)≈0.27]
```

softmax 让类别分数转成和为 1 的概率形式。当前 `unsafe_score=P(unsafe)=1-P(safe)`；safe 来自原始数据的 sec 标签，因此与计划中的 `1-P(sec)` 对应。尚未做概率校准，0.73 不能当作已经验证的客观风险频率。

### 2. threshold：业务如何使用这个分数

我们固定判定规则为：

```text
unsafe_score >= threshold → 判为不安全 / 拦截
unsafe_score <  threshold → 判为安全 / 放行
```

同样是上面约 0.73 的教学分数，门槛 0.5 会拦，门槛 0.8 会放行。模型参数和分数不变，变化的是业务决策。

当前两类 argmax 通常对应 0.5 门槛，平分时按 unsafe=0 处理。脚本先用原始 logits 的 argmax 复现训练报告的计数，再用双精度 softmax 分数选择新阈值。

提高阈值会让拦截集合缩小，误拦可能减少，漏判可能增加；降低阈值则反过来。阈值不能把本来混淆的文本“重新学会”，也不能恢复被截断的输入。

### 3. 约束和目标：用你的实际数据决定

本验证集有安全 40 条、不安全 40 条。当前已保存模型的 argmax 结果：

| 模型 | 不安全识别 / 漏判 | 安全放行 / 误拦 |
| --- | --- | --- |
| 基线第 3 轮 | 19 / 21 | 38 / 2 |
| LoRA 第 2 轮 | 33 / 7 | 29 / 11 |

误拦率的分母是**真实安全回复数**，LoRA 是 11/40=27.5%，不是 11/80。10%×40=4，意味着当前验证集最多误拦 4 条安全回复。基线还有降低门槛以提高召回的可能；LoRA 需要更高门槛减少误拦，最终数值要看真实分数，不能从这张计数表直接推出来。

事先固定选择顺序：

1. 只保留安全误拦率≤10% 的阈值。
2. 在这些阈值中，选择不安全召回率最高的。
3. 若召回相同，选择误拦更低的；两者仍相同，选择较低阈值，保证规则确定。

脚本检查实际分数边界并加入 0、0.5、1，不凭空指定 0.7 或 0.8。若在 [0,1] 找不到满足约束的门槛，明确报告不可行，不偷偷放宽约束；两种模型均可行才写出阈值配置。

## 指标怎样读

| 指标 | 含义 | 当前任务中的职责 |
| --- | --- | --- |
| Accuracy | 判对数 / 总样本数 | 总体观察，不能单独表示风险拦截能力 |
| 不安全召回率 | 正确识别的不安全数 / 真实不安全总数 | 在误拦约束下尽量提高 |
| 安全误拦率 | 判成不安全的安全数 / 真实安全总数 | 当前要求不超过 10% |
| Precision | 判成某类的样本中，真实属于该类的比例 | 与 recall 共同组成该类 F1 |
| Macro-F1 | 分别计算两类 F1，再取平均 | 两类同等权重，用于总体比较；本次阈值目标不是最大化它 |
| 混淆矩阵 | 行为真值，列为预测 | 顺序 unsafe/safe，能直接读出误拦、漏判数量 |

训练时按 Macro-F1 选 checkpoint，当前按业务约束选阈值，这是两个不同决策。此时固定已保存的模型轮次，不为了某个结果重新训练或用 test 改轮次。

## 由学习者执行

```powershell
uv run --no-sync --offline --no-python-downloads python .\scripts\select_threshold.py
```

不增加新依赖。脚本先读取：

- `data/processed/stage-3/validation.jsonl` 以及阶段 3 manifest。
- `reports/stage-4-baseline.json`、`reports/stage-5-lora.json`，核对验证文件和标签版本，并找出已选择轮次的计数。
- `artifacts/frozen-baseline/model/`：重载完整基线。
- `artifacts/base-model/` ＋ `artifacts/lora-safety/adapter/`：显式本地重载基础模型并挂载 adapter，核对基础文件 SHA256。

这次没有 optimizer、backward 或参数更新。两种模型逐个在 CPU 上评分，不同时驻留两套完整模型。它也是真实 adapter 的首次重载评分验收：原规则的混淆矩阵必须与训练报告最优轮次一致，否则停止选择阈值，先排查 checkpoint、标签或编码设置。

| 参数 | 默认值 | 作用 |
| --- | --- | --- |
| `--max-safe-fpr` | 0.1 | 验证集安全误拦上限；当前实验固定，不随结果临时放宽 |
| `--batch-size` / `--threads` | 8 / 4 | 推理批量大小、CPU 线程数 |
| `--validation` / `--manifest` | 阶段 3 对应文件 | 明确评分数据与标签约定 |
| `--baseline-dir` | frozen-baseline/model | 基线 checkpoint |
| `--base-model-dir` / `--adapter-dir` | 本地基础目录 / lora-safety/adapter | LoRA 的配套资源 |
| `--baseline-report` / `--lora-report` | 两份完整训练报告 | 核对来源和重载后预测计数 |
| `--report` | reports/stage-6-validation.json | 只保存无原文的汇总指标 |
| `--decision-file` | artifacts/evaluation/thresholds.json | 保存选定门槛、长度、标签、模型路径与文件指纹 |

长度沿用各自训练报告的 128，不能在本次评测中悄悄改长度。LoRA 基础模型构建时可能仍提示分类头新初始化，随后加载 adapter 会恢复训练后的分类头；以重载后的预测计数核对为证据。

## 本次产物和验收边界

当前代码和合成工程测试已准备，真实阈值尚未由学习者运行产生，不预填阈值数值或承诺 LoRA 在同样误拦上限下仍然更好。

两种模型均满足约束时，写出 `artifacts/evaluation/thresholds.json`：把“哪份模型文件、哪套标签和长度、哪个判定门槛”绑定起来。配置已存在时脚本拒绝覆盖，复跑验证实验需显式指定新 decision-file，避免悄悄改掉已冻结的决策。该文件与报告均在 Git 忽略目录。

当前最多误拦 4/40 只是这份验证集上的结果，不保证未来样本误拦率也≤10%。少量验证样本、阈值选择本身的适配、长文本截断等局限仍需由最终 test 观察。不能为了让 test 达标反复改阈值再测。

实际验证输出核对后，再准备最终 test 验收入口与指令；本次脚本没有 test 数据入口。
